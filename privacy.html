Privacy Policy

Tackboard — a local tool for publishing Pins to a Pinterest account

Last updated: 20 October 2026 · Effective date: 20 October 2026

In one sentence: Tackboard runs entirely on the operator's own computer, has no server and no analytics, and the only Pinterest data it writes to disk is the identifier of a Pin it created itself.

1. Scope of this policy

This policy covers Tackboard, a command-line application that creates boards and Pins on a Pinterest account through the Pinterest API v5. Tackboard is operated by a single individual and is used to publish that individual's own content. There is no hosted version of the application, no sign-up, and no third-party service that operates Tackboard on the operator's behalf.

Tackboard is an independent application. It is not affiliated with, endorsed by or sponsored by Pinterest. Pinterest's own privacy policy governs the Pinterest account and the Pinterest service, and applies separately to any data Pinterest receives through the API.

2. What Tackboard is

Tackboard runs four local stages. It collects search keywords from public search-engine autocomplete endpoints, drafts a pin plan from a chosen keyword, composes a 1000×1500 pin image and its text locally, and publishes the result to the operator's Pinterest account with a single API call. The operator can run each stage separately and inspect the output before anything is published.

3. Information the application collects

All collection happens on the operator's own machine, and every item in this list is either a credential the operator issued or content the operator created.

3.1 OAuth credentials

The application stores the Pinterest app id, the app secret, the OAuth access token and the OAuth refresh token in a local file named secrets.yaml in the project directory. That file is excluded from version control and, where the operating system supports it, its permissions are restricted to the owner. No Pinterest password, no Pinterest session cookie and no other login credential is ever requested, read or stored.

3.2 Content the operator creates

The application writes the keyword lists, niche scores and pin plans that the operator generates to JSON and CSV files inside the project directory, together with the rendered pin images and the command logs produced by the scheduled task. The pin plan contains the locally generated title, description, alt text and outbound link, the identifier of the Pin the application created, and the status of that Pin. It does not contain the content of any other Pin, board or account.

3.3 Affiliate and product identifiers

The operator may configure identifiers for an external affiliate programme, such as a Rakuten affiliate id, an Amazon Associates partner tag or Awin identifiers, together with a product list in CSV or JSON format. These are supplied by the operator and stored locally in the configuration file and in the product list.

4. Information the application does not collect

Tackboard does not collect, request, receive or transmit:

  • your Pinterest username, password, email address or session cookies;
  • the content of Pins, boards, profiles, followers or analytics belonging to any Pinterest account other than the one the operator authorizes, and in practice it does not retain that content for its own account either;
  • contact lists, location data, device identifiers, advertising identifiers, or behavioural or usage data about the operator or any visitor to a website, because the application is not a website and has no telemetry, analytics or crash-reporting component;
  • information from children under the age of 13. The application is not directed at children and is not intended for use by them.

Tackboard also never scrapes Pinterest, and it never uses Pinterest to target people with advertising outside Pinterest.

5. Pinterest API responses are not stored

The Pinterest Developer Guidelines state that, apart from campaign analytics information accessed about your own account, you may not store any information accessed through any Pinterest Materials including the API, and that you should call the API each time you need the information. Tackboard is built to that rule.

Read endpoints are used transiently. The responses from GET /v5/boards, GET /v5/boards/{board_id}/pins, GET /v5/pins/{pin_id} and GET /v5/user_account are held in memory for the length of a single command, used to resolve a board id, to confirm that a newly created Pin exists, or to print a status line for the operator. They are not written to the application's data files, and they are not sent anywhere.

The single exception, stated plainly: the application writes the identifier of a Pin it created itself into its local plan file. The identifier is used for two purposes only: to avoid publishing the same Pin twice, and to allow the application to delete its own Pins on request. No Pin title, description, image, link or board content returned by the API is persisted.

6. How information is used

Information is used only to operate the publishing workflow: the tokens authenticate API calls, the keyword and product lists are the inputs the operator chose, the generated images and text become the Pin, and the logs are kept so the operator can review what ran. The information is not used for advertising, profiling, reselling, model training or any other purpose, and it is not combined with data from any other service.

7. Sharing and third parties

Tackboard shares nothing with third parties. The data that leaves the operator's computer is limited to the requests the operator has configured:

  • Pinterest receives the board and Pin data described in this policy, and receives the outbound link and the affiliate parameters attached to it.
  • Search engines (Google, Bing, DuckDuckGo) receive the seed and expanded keyword queries used during the research stage. These are ordinary search queries and are not linked to any Pinterest account.
  • Affiliate and product networks (for example Rakuten, Amazon Associates, Awin) receive a product search request, and later receive a click on an affiliate link if a reader follows one.
  • An optional language model provider receives a keyword and a short product title when the operator enables the optional copy-generation mode. This mode is off by default and the provider is chosen by the operator.

8. Affiliate disclosure and advertising compliance

The Pins produced by this application are commercial content. Every description includes a clear disclosure that the links are affiliate links and that a commission may be earned at no extra cost to the reader. The application refuses to publish a pin whose description is missing that sentence, so a non-compliant pin cannot be sent by the application. The disclosure text currently reads: “Affiliate disclosure: some links are affiliate links and we may earn a commission at no extra cost to you.”

Outbound links carry UTM parameters, namely utm_source, utm_medium, utm_campaign and utm_content, so the operator can measure which pin produced a click. The application does not generate shortened URLs, because Pinterest does not support them. The operator is responsible for complying with the disclosure rules that apply to them, including the US Federal Trade Commission endorsement guides, and the application supports that obligation by making the disclosure automatic rather than optional.

9. AI-generated content

Pin images are composed programmatically by the application rather than photographed by the operator. Every pin it creates is therefore submitted to Pinterest with the ai_disclosures field set to AI_MODIFIED, which is the label Pinterest provides for a creative altered by an automated tool. Tackboard does not generate photorealistic images of people, does not imitate any individual's likeness, and does not create images designed to deceive.

10. Retention

OAuth tokens remain in secrets.yaml until they are refreshed, revoked by the operator, or deleted. The operator can delete the file at any time; after that the application cannot call the API until the authorization flow is repeated. Plan files, keyword files, product lists and logs are kept only as long as the operator keeps them on disk, and the operator can delete them individually or delete the whole project directory. The application uploads nothing to a backup service, a cloud drive or any other remote store.

11. Your rights and how to exercise them

Because the application is local and single-user, the fastest way to exercise any right over the data is to act on the machine that holds it.

Access

The operator can inspect everything the application holds by opening secrets.yaml and the JSON and CSV files in the project directory, and can have the application list the boards and Pins on the authorized Pinterest account with the boards and pins commands.

Deletion

To remove local data, delete the file or directory in question. To remove the tokens, delete secrets.yaml. To remove Pins or boards that the application created on Pinterest, delete them from Pinterest, or use the application's delete call for a pin it created. To withdraw the authorization itself, use the account settings on Pinterest or the My apps page on the Pinterest developer portal; the application will then receive an authentication error on every call.

Contact

Requests about this policy, about the data the application holds, or about the Pinterest account involved can be sent to seiseimelon@gmail.com. The operator aims to respond within a few business days. A request can also be raised with Pinterest directly, through the Pinterest Help Center, if it concerns data Pinterest itself holds.

12. Security

Credentials are kept in a single local file that is excluded from version control, and file permissions are restricted to the owner where the operating system supports it. The application makes no outbound request other than to the services listed in section 7, and it does not transmit credentials to any of them except to Pinterest, where they are required. The application does not attempt to evade Pinterest's rate limits, and it treats a 429 response as a signal to wait rather than as an obstacle to route around.

13. Changes to this policy

This policy may be updated as the application changes. The date at the top of the page shows the last update, and the history of changes is kept with the project source. Material changes will be reflected in the description submitted to the Pinterest developer portal, because the two documents are reviewed together.
